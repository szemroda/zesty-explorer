Phases 5–10

Deliver the explorer in vertical slices.

Start with a useful root collection browser. Add orchestration, relationships, querying, recursive presentation, and sharing only after the previous slice behaves correctly.

  1. Ship the root vertical slice
  2. Orchestrate snapshots and loading
  3. Build the relationship engine and tree editor
  4. Add filtering, sorting, and pagination
  5. Render recursive tables and item details
  6. Synchronize and share the view
5

Ship the root vertical slice

Depends on: phase 4Milestone: M2 begins
  • Build the compact dark application shell: top bar, empty/start state, left tree region, main table region, and right Sheet region.
  • Add the password-style session-token input with reveal, clear confirmation, and a helper for production, stage, and development cookie names.
  • Add the root collection reference input, accepted examples, validation feedback, and collection-link helper.
  • Connect one parsed root collection to TanStack Query and the Effect-backed ZestyApi.
  • Render the root collection with generated columns, default modified descending sort, technical fields hidden, horizontal scrolling, and root pagination at 100 rows.
  • Add the view-wide Published only control and explicit Refresh action.
  • Open item details automatically when the initial collection reference contains an item ZUID.
  • Implement root loading, empty, authentication, permission, missing collection, decoding, network, and retry states.
  • On 401, clear the token, preserve the root reference, reopen token entry, and resume after replacement.

Output: the first genuinely usable product slice: open, browse, inspect, switch state, and refresh one collection.

Exit gate: a fake-backed browser test covers the entire start-to-root-table flow, including token recovery and item deep-link details.

6

Orchestrate snapshots and loading

Depends on: phase 5Milestone: M2
  • Define TanStack Query identities by instance, deployment, collection, content state, and en-US.
  • Cache each unique collection snapshot once even when the collection has several nodes in the tree.
  • Load the root first, then configured descendants with at most three collection requests running concurrently.
  • Cancel superseded loads when the root, content state, or view changes.
  • Enforce the 10,000-item per-collection and 50,000-item per-view limits during pagination and orchestration.
  • Represent complete, partial, pending, stale, failed, and successful snapshots explicitly.
  • Keep usable snapshots visible during explicit refresh and preserve expansion for item IDs that still exist.
  • Ensure Effect owns request retry while TanStack Query does not introduce a second retry loop.

Output: predictable, cancellable snapshot loading with no duplicate collection fetches.

Exit gate: orchestration tests prove root-first order, concurrency ≤ 3, deduplication, cancellation, partial limits, and no double retry.

7

Build the relationship engine and tree editor

Depends on: phases 2 and 6Milestone: M3 begins
  • Implement pure ExplorerCore normalization over stable content-item IDs and immutable snapshot references.
  • Read model schemas and identify native relationship fields that target the selected child model.
  • Require user choice when multiple native fields are valid; never guess an ambiguous relationship.
  • Support custom parent and child nested scalar field paths with strict typed equality and no coercion.
  • Build Map<scalar, item IDs[]> child indexes once per snapshot and relationship definition.
  • Preserve all matches, unmatched parents with empty child lists, and children referenced by several parents.
  • Build the left-side relationship tree editor with add, rename, and confirmed subtree removal.
  • Enforce one instance, one deployment, an acyclic tree, maximum depth five, and maximum ten nodes before loading a child.
  • Allow the same collection in several role-specific nodes while sharing its fetched snapshot.
  • Mark schema-stale paths invalid without discarding the node or the remainder of the view.

Output: a validated collection-node tree and indexed relationship results independent of React.

Exit gate: relationship tests cover cardinality, duplicate roles, strict type equality, missing values, cycles, depth, node limits, and stale paths.

8

Add filtering, sorting, and pagination

Depends on: phase 7Milestone: M3
  • Implement pure field-path resolution that distinguishes missing, null, scalar, structured, and invalid values.
  • Implement text, number, date, boolean, empty, and closed-value-set operators from the specification.
  • Combine separate filters with AND and multi-select values with OR.
  • Implement descendant predicates with any semantics without filtering the retained related-items list.
  • Implement the global free-text search across root and descendants, excluding technical metadata and raw JSON.
  • Strip HTML tags and compare text case-insensitively without executing or injecting markup.
  • Implement node-level table free text, column filters, and path-based filters that limit rows but preserve ancestors.
  • Implement one sort field per node, default modified descending, stable ordering, and nulls last.
  • Implement root and per-parent nested pagination with 25, 50, and 100-row options.
  • Memoize derived ID sets by snapshot identity and relevant view state; calculate facet options only when their control opens.
  • Debounce text inputs by 200 ms, show progress only after another 300 ms, and ignore superseded calculations.

Output: deterministic query primitives and UI controls shared across root and nested tables.

Exit gate: unit tests exhaust operator/null semantics and prove that view filters, table filters, and retained relationships remain distinct.

9

Render recursive tables and item details

Depends on: phases 7–8Milestone: M3
  • Create one recursive nested-table component bounded by the validated five-level tree.
  • Start every relation collapsed, allow several expanded rows, and mount nested content only while expanded.
  • Give each node shared columns, widths, filters, and sort while keeping page numbers local to each parent occurrence.
  • Render all content fields by default and keep technical metadata plus raw JSON hidden until selected.
  • Add column visibility and resizing, a sticky leading actions column, horizontal scroll, and compact node toolbars.
  • Truncate long values and route hover or explicit interaction through one controlled, keyboard-accessible popover.
  • Render structured and HTML values safely as readable text.
  • Add separate row actions for relation expansion, details, and opening the matching Zesty Manager item.
  • Build the right-side details Sheet with all fields, technical metadata, raw JSON, per-value copy, visible close, and focus restoration.
  • Display loading, partial-data, and failed-descendant states at the affected node without blocking healthy nodes.

Output: the complete nested browsing experience with bounded rendering work.

Exit gate: component and browser tests cover five-level nesting, repeated node occurrences, independent paging, shared node state, details, popovers, and partial children.

10

Synchronize and share the view

Depends on: phases 5–9Milestone: M3 completes
  • Hydrate the application from the URL fragment before starting collection requests.
  • Synchronize settled non-secret state through history.replaceState without adding history entries while typing.
  • Include root and child references, deployment, content state, relations, names, filters, columns, widths, and sorts.
  • Exclude token, expansion, pages, open panels, request state, and temporary input state.
  • Add Copy view link and warn when the encoded URL exceeds 8,000 characters.
  • Restore a valid view after reload using URL state plus a token read separately from sessionStorage.
  • Offer copy-raw and confirmed reset actions for invalid, truncated, or unsupported payloads.
  • Implement confirmed Reset view while preserving the session token.
  • Implement confirmed root replacement and subtree deletion summaries before destructive view changes.
  • Add version-migration tests and golden URL fixtures so future codec changes remain deliberate.

Output: reload-safe, credential-free share links and recoverable URL-state failures.

Exit gate: opening a copied URL in a second tab reconstructs the same view but requires that tab’s own session token.

Explorer completion check

  • One view can contain ten nodes across five levels without duplicate collection requests.
  • Published state is global and consistent across every node.
  • Changing one node’s filters, columns, or sort updates all rendered occurrences of that node.
  • Expansion and nested page numbers do not inflate shared URLs.
